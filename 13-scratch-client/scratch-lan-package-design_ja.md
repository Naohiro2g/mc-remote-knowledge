# Scratch LANパッケージの設計

LANパッケージは、箱庭で体験したことを、家庭や教室のネットワークの中で続けるための配布物の総称である（`2026-10-13-02`）。
本書はそのうちScratchが配る**Scratch LANパッケージ**の、取得から再開・更新までの体験を扱う。定義は`2026-10-07-04`
（標準のケータリング型から、OCI、証明書、Stackのpreset／orderを除いたもの）、体験の目標は`2026-10-12-01`（箱庭サーバーに
Chromeでつなぐのと同じ難易度と簡便さ）。将来McRemoteが配る**Paper＋プラグイン LANパッケージ**（Paper、McRemote、
おすすめプラグインのセットアップ）と併せてLANパッケージとなる。

出典はScratch担当とhuman ownerの設計対話（scratch-editor `mc-remote/local/LAN_EXPERIENCE_DESIGN_ja.md`、2026-10-13）。
教材の部分（共通教材、整地とXYZ軸、マイクラ課題）はRCの間に`20-教材`へ収録する。

## 1. 誰のための、何か

入口は箱庭である。用意された環境で一度「Scratchからマイクラを動かせた」と経験すると、「普段遊んでいるワールドでも
使いたい」という欲求が生まれる。子どもにも経験のあるOSS利用者にも自然な流れで、LANパッケージはこれに応える。
「LAN」は箱庭の体験を自分たちのネットワークへ持ち込む意味で、1台のPCですべて動かす場合も含む。

- 箱庭を強く勧めるが、手順を覚えてくることは求めない。忘れることは失敗ではない。翌日、一か月後、別のPCでも、
  見ながらもう一度進められるようにし、接続、ペアリングの案内を操作する場所に置く
- 年齢を理由に仕組みを一律に隠さない。経験者だけが知る手順を、説明なしに要求しない
- 学習の本体は箱庭と共通にし、LAN固有の案内は、取得、置き場所、起動と終了、接続先、再開、更新に絞る

## 2. 呼び名と構成

全体は「マイクラリモコン」（`mc-remote`、`mc-remote.com`）、`McRemote`はMinecraftサーバーへ入れるプラグインの名前。
利用者向けの説明で「サーバー」を単独で使わず、マイクラサーバー、Scratch用HTTPサービス、Bridgeなど対象を明記する。
最初に要る理解は二つだけ：マイクラアプリでワールドに参加する、ブラウザのScratchからそのワールドを操作する。

設定の入口は「マイクラサーバーは、どのPCで動いていますか？」とし、「このPC」「LAN内の別のPC」から選ぶ。

| 項目 | このPC | LAN内の別のPC |
| --- | --- | --- |
| パッケージを動かす場所 | Scratchを使うPC | Scratchを使う各PC |
| 接続先 | `127.0.0.1` | マイクラサーバー役のPCのIPアドレスかホスト名 |
| McRemoteのTCPポート | 通常`25575` | 通常`25575` |

マイクラサーバーの準備は、当面McRemote READMEのクイックスタート（Javaはmise、`2026-10-12-02`）が受け持つ。Minecraftに
参加するポートとリモコンのポートを混同させない。

## 3. 取得

ホームページから自分のOSのZIPを一つ選ぶ。ボタンは人が選べる名前、ファイル名は識別できる名前にする。

| ボタン | ZIP |
| --- | --- |
| Windows用 — Intel／AMD 64ビット | `mc-remote-scratch-LAN-<version>-windows-x64.zip` |
| Mac用 — Apple Silicon（Mシリーズ） | `mc-remote-scratch-LAN-<version>-macos-arm64.zip` |
| Linux用 — Intel／AMD 64ビット | `mc-remote-scratch-LAN-<version>-linux-x64.zip` |

置き場所はscratch-editorのRelease asset。利用者にソースZIP、OCI、単体WireScopeなどを仕分けさせない。検証も同じ経路で
行う（`2026-10-13-05`）。利用者にはハッシュの照合を求めず、検証したZIPと公開するZIPの同一性は開発側が記録する。

## 4. 置き場所と中身

置き場所は`HOME/mc-remote/mc-remote-scratch-LAN/<version>/`（`2026-10-13-03`）。ダウンロードフォルダーで偶然起動できた
状態を導入の完了としない。初回の案内に、置き場所への配置と、フォルダーのお気に入りまたは起動ファイルのショートカットを含める。

```text
HOME/mc-remote/
├─ mc-remote-scratch-LAN/
│  └─ <version>/
│     ├─ start-mc-remote.cmd（macOSは.command、Linuxは.sh）
│     ├─ settings.json（設定を保存した後にできる）
│     ├─ data/（identity.json、wirescope-app.manifest.json、実行環境など）
│     ├─ README_ja.md
│     ├─ はじめに.html
│     └─ NOTICE_ja.md
└─ clients/
   └─ scratch/
      ├─ projects/
      └─ sprites/
```

- 最上位は起動ファイルが見つかる数に絞る。`SOURCE_ja.md`は置かず、ソースへの案内はREADMEと「はじめに」に入れる
- `はじめに.html`は、起動に失敗しても、Markdownを読むアプリが無くても読める案内。READMEと同じ元から作り、二重に管理しない
- `settings.json`は起動ファイルの隣に置き、設定がどこにあるかを見えるようにする。普段の編集の入口は設定画面
- 版は版ごとのフォルダーに置く。版はフォルダー名のほか、「はじめに」と設定画面でも分かるようにする
- 展開ツールが外側に同名のフォルダーを足すことがあるので、案内の到達点は「起動ファイルと`data/`が並ぶ場所」とする

## 5. 起動と終了

ダブルクリックで安定して起動できるOSはそれを主な経路にし、できないOSは最初からターミナルで案内する。クリックの数でなく、
迷わず再現できるかで決める（実物で評価）。Windowsのターミナルの案内はGit Bashを正準とし、PowerShellでも同じコマンドを
案内する（b10のRelease本文。PowerShell 5.1と7.6.7で確認済み、2026-10-14）。

| OS | 主な経路の候補 | ターミナルの経路 |
| --- | --- | --- |
| Windows | 展開の前にZIPのプロパティで「許可する」にチェックし、`start-mc-remote.cmd`をダブルクリック | フォルダーでGit Bashを開き`./start-mc-remote.cmd` |
| macOS | `start-mc-remote.command`をダブルクリック | フォルダーをターミナルで開き`./start-mc-remote.command` |
| Linux | フォルダーを端末で開いて起動 | `./start-mc-remote.sh` |

コード署名と公証はしない（`2026-10-14-01`）。OSが起動の前に求める確認は、OSごとに案内する。

- Windows：Smart App Controlが有効だと、ダウンロードの印の付いた署名の無い起動ファイルのダブルクリックが止められる。
  展開の前にZIPのプロパティで「許可する」にチェックすれば、展開したものに印が付かず、ダブルクリックで起動する。
  チェックは展開の前の操作なので、ZIPの中の案内でなく、取得するボタンのそばで案内する（§3）。ターミナルの経路も
  案内する。Microsoft Storeへの登録は主に宣伝の目的で検討する。Smart App Controlを切る
  方法は手順に入れない
- macOS：初回だけ「プライバシーとセキュリティ」の「このまま開く」が要る。2回目からはダブルクリックで起動する
- Linux：ダブルクリックでテキストエディターが開くことがある。右クリックの「プログラムとして実行」でも起動する

ランチャーが開く設定画面は、接続先などを決める画面である。保存してScratchを開いた後は、閉じても使い続けられる。
ダブルクリックでもターミナルでも設定画面を通るので、起動後の案内はここへ集める。二回目以降は保存した接続先でScratchを
開き、毎回の保存を求めない。自動でScratchが開くことと、マイクラへの接続が成り立つことは分けて案内する。

コンソールは邪魔な画面として消すのでなく、何を出し、どこで読めるかを直す。ダブルクリックでコンソールを出さない構成も
評価する。その場合は、出力を見る方法、終了の方法、閉じた設定画面を開き直す方法、設定画面が開く前の失敗の見つけ方を
併せて決める。

## 6. 再開と更新

普段の始め方は「マイクラサーバーが動いているのを確かめて参加する → いつもの起動ファイルを開く → 作品を開いて接続する」。
ブラウザのブックマークだけではランチャーは起動しないので、再開の案内はPC上の起動ファイルから始める。共有している
マイクラサーバーを止める操作と、各PCのScratchを終える操作は分ける。

新しい版は旧版に上書きせず、隣の版のフォルダーに置く。「取得・展開 → 新しい版を起動して確認 → 普段の入口を新しい版へ
変える → 旧版は当面残す」の順。Scratchのアドレス（`127.0.0.1:8601`）は版をまたいで変えない。変えるとブラウザ保存の領域が
変わり、作品が消えたように見える。`settings.json`の引き継ぎと、旧版へ戻したときの設定は未決。

## 7. 作品の保存

最初はブラウザ保存を主に案内する。作品を作り、同じブラウザから続きを開けることを先に経験し、ファイルの管理を理解して
から始める順にしない。ただし「別のブラウザや別のPCでは自動で現れない」「大切な作品はファイルにも保存できる」という
境界は伝える。

ファイルの保存先は`HOME/mc-remote/clients/scratch/projects/`（`.sb3`）と`sprites/`（`.sprite3`）で、パッケージの版の
フォルダーから独立させる。書き出しの方式は`13-scratch-client/scratch-project-storage-transfer-design_ja.md` §14で、
入れるのは初回stableの後（b10とrc1はブラウザ保存とファイルのダウンロード。それまで案内でこの置き場所への保存を約束しない）。

`.sb3`をOS上でダブルクリックしても開かないので、教材のファイルは取得ボタンのすぐ近くで「Scratchの『ファイル』→
『コンピューターから読み込む』で開く」と案内する。開いているScratchの画面へ`.sb3`をドラッグ＆ドロップしても開ける（b10。
読み込みの前に今の作品をブラウザに保存する、storage design §8）。3 OSの配布ZIPで確かめた後に主な経路の候補とする。

## 8. 人間チェック

ホームページで配布物を選ぶところから始め、実際の配布ZIP、取得の方法、OS標準の展開を使う（`2026-10-12-01`）。開発者が
用意したフォルダーで接続できたことと、利用者の導入を通せたことを分ける。

| 場面 | してもらうこと | 見たいこと |
| --- | --- | --- |
| 選択・取得 | ホームページで自分のOS用をブラウザで取る | 開発用の成果物を仕分けずに済むか |
| 展開・配置 | ZIPを展開し、使い続ける場所へ置く | 二重のフォルダーで迷わず、起動ファイルを見つけるか |
| 案内を読む | 起動の前に`はじめに.html`を開く | 追加のアプリなしで読めるか |
| 初回起動 | ダブルクリック、または案内した端末の操作 | 警告、実行権限、ブラウザの起動まで案内で進めるか |
| 設定画面 | 保存の後に設定画面を閉じ、必要なら開き直す | Scratchを使い続け、案内と詳しい出力に行き着くか |
| 1台／LAN | 接続、ペアリング、小さな操作。LANでは別PCのサーバーへ | どのPCで何をするか分かるか |
| 複数人 | 複数のPC、各自のプレイヤー | 各自の接続とペアリングを混同しないか |
| 保存・再開 | 作品を保存し、翌日に開き直す | 起動場所と作品を見つけるか |
| 更新 | 新しい版を隣に置き、普段の入口を変える | 起動する版を見分け、設定の引き継ぎが分かるか |
| つまずき | サーバーの停止、接続先の違いなど | 案内から次の操作を選べるか |

結果は観察のまま記録し、判断は結果から行う（human owner 2026-10-14）。再開の試験では作者が横で誘導しない。OSの警告を見る回は、
各PCのブラウザで配布元から取る。起動ファイルと同梱の実行環境の警告は分けて記録する。
