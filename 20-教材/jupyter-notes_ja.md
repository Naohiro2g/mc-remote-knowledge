## 1. .py を書き換えたらカーネル再起動 — autoreload は勧めない

> 2026-09-28 書き直し。human owner の見解（2026-09-27）「autoreload は使いにくく、実質使えない。.py を書き換えたらカーネル再起動を勧める。それが明確にガイドされていれば問題ない」を反映した。旧版の「autoreload をおまじないとして置く」方針は撤回する。

### 現状

セル冒頭に以下が「おまじない」として置かれている（説明なし）。

```python
%load_ext autoreload
%autoreload 2
```

`param_mc_remote.py` や `axis_flat.py` など自作 .py を編集したとき、カーネルを再起動せずに読み直すための仕組みである。

### autoreload を勧めない理由

- 関数やメソッドの中身の変更には追従するが、クラスの構造の変更（属性の追加など）や、`from module import 名前` で取り込んだ名前には追従しきれないことがある。
- 追従しなかったとき、学習者には「直したのに変わらない」としか見えず、原因にたどり着けない。
- 既に作ったインスタンス（例：`mc = Minecraft.create(...)` の `mc`）は、どの読み直し方でも古いままで、作り直しが要る（Python 担当の実験、2026-09-28、`2026-09-28-01`）。
- カーネル再起動なら、書き方に関係なく確実に反映される。

### 方針（全体作業時に反映）

> 2026-09-28 改訂：human owner の見解（2026-09-28）を反映した。「再起動して全セルを実行」の案内と、「ノートブックを上から通しで実行できる形に保つ」を取り下げた。

- ノートブックから `%load_ext autoreload`／`%autoreload 2` のセルを外す。
- 書き換えが反映されない理由は、「import したモジュールはキャッシュされ（`sys.modules`）、ファイルを変えても自動では更新されない」と説明する。キャッシュの仕組みを理解する機会として扱う。
- 添えるガイドは最低限にする。例：「カーネルを再起動したら、import や `mc` の設定など、サーバーとの接続もやり直しが要る。ただし上から全部実行するのはおすすめしない」。
- 全セルの実行を勧めない。ノートブックには試行錯誤の途中の断片や、並べて比べる別案を置くことを想定しており、矛盾する内容やエラーになるセルが一緒に動いてしまう。
- 何を初期化してから実行するかは、ルールやガイドで決めず、学習者に任せる。提供するテンプレートを使ううちに自然と身につくことを目指す。
- .py 版（`hello.py` など）では、保存して実行し直せば読み直されるので、この案内は要らない。
- `mc_remote` 自体を改造する学習者にも同じ説明を使う（README の Jupyter の節、minecraft-remote-api PR #11 と揃える）。

## 2. Jupyter特有のパス問題（最大の地雷）

### 現状

セル[11]の説明「同じ階層にあるからインポートできる」は、
**ノートブックの場所 = カレントディレクトリ(CWD)** という暗黙の前提に立っている。

### 問題

- Jupyter は「.ipynb があるディレクトリ」を起点にしがち。
- VS Code でノートブックを開くと **ワークスペースのルート**が CWD になることがある。
- ここがズレると `import param_mc_remote` / `import axis_flat` が
  突然 `ModuleNotFoundError` になる。
- 利用者の実行環境が VS Code / Jupyter Lab / Google Colab / クラウドでバラバラ
  なため、対象年齢を考えると説明 or 吸収が必須。

### 改善方針（全体作業時に反映）

プロジェクト全体の `mc_constants.py` 自動生成アーキテクチャの
「生成先CWD一本化 + sys.path.insert」方針と地続き。同じ考え方を教材にも適用する。

選択肢（コスト低い順）:

1. **`.vscode/settings.json` を同梱**し `jupyter.notebookFileRoot` /
   `executeInFileDir` 等で **CWD をノートブックの場所に固定**する。
   → 説明コスト最小・最も確実。既存の `.vscode` 同梱方針と噛み合う。
2. 冒頭「おまじない」セルで sys.path にサンプルディレクトリを追加。
   - Jupyter では `__file__` が使えないため `os.getcwd()` ベースになる。
   - 文字列化した `"__file__"` を使う書き方はトリッキーで教材向きではない。
3. Colab / ローカル で出し分け（環境ごとに別セル）。説明コスト高め。

→ 第一候補は **1（.vscode 同梱で CWD 固定）**。

## 3. その他、教材に効くJupyter注意点

### sleep() 多用時のブロッキング

- セル[20][22]等で `sleep()` 多用（マイクラの描画を見せるため必須）。
- セル実行中はカーネルがブロックされる。止めるには「停止（■）」ボタン。
- 知らない学習者が「固まった」と勘違い→セル再実行→**mc接続が多重化**する事故。
- 最初の sleep 登場あたりで「長く待つセルは ■ で止められる」を一言添える。

### 実行順序依存の見えない状態

- セル[3]で `PLAYER_NAME` 定義 → セル[5]で使用、という
  **上から順に実行する前提**。
- 学習者がセルを飛ばす/戻ると「変数が無い」「古い mc 接続が残る」など
  初心者に原因が見えない不具合。
- 改善案: 接続セル[5]/[13]に「再接続しても安全」なガードを入れる
  （既存接続があれば閉じて張り直す / PLAYER_NAME 未定義なら分かりやすい
  メッセージ）。ガードは関数に隠して「おまじない」側に寄せれば見た目はシンプルなまま。
