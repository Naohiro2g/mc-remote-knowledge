# XYZ軸の空間で建てる教材の設計

最初のコマで、Scratchから箱庭サーバーにつなぎ、XYZ軸のある空間でブロックを置いて形を作る教材の設計記録。すぐ隣に置く、
上に置く、を繰り返すうちに、x、y、zの感覚が操作と結びつく。空間図形は中学1年で習うが、マイクラに親しんでいる小学生なら
この入口で困らない（human owner 2026-10-20）。

範囲は限る。Scratchで、箱庭サーバーにつないで、最初のコマでできる内容を扱う。LANパッケージから入った人も、接続とペアリングの
後は同じ教材に合流する（[Scratch LANパッケージの設計](../13-scratch-client/scratch-lan-package-design_ja.md) §1）。Pythonで同じ形を
作ることは、後で同じ空間へつなぐ（§6）。

出典：Scratch担当とhuman ownerの設計対話（scratch-editor `mc-remote/local/LAN_EXPERIENCE_DESIGN_ja.md` §3、§10、§11、develop
`0809eb5e49e4b83c17a4e91b435d151b9d1b0655`）、human ownerがこれまで使ってきた教材（「Scratchでマイクラのリモコン 入門編」
2022-07-26、「マイクラ課題」2021、Pythonの`axis_flat.py`）、human ownerの説明（2026-10-20）。教材の実物は、human ownerが今
Pythonとの対応も含めて作り直している。この文書は実物の細部が変わっても残る設計の理由を書き、実物の名前、版、置き場所、
数値は実物が固まってから足す（§7）。

## 1. 流れ

```text
箱庭：マイクラサーバーに参加 → 箱庭Scratchを開く ─────┐
                                                       ├→ 接続・ペアリング
LAN ：取得 → 展開 → 起動 → 接続先を設定 ───────────┘
    → 教材を読み込む → 整地・XYZ軸 → 置いてみる → マイクラ課題・自分の制作
```

教材は箱庭とLANで分けて育てない。合流した後の説明は一つにし、必要な箇所をその場で読めるようにする。箱庭で経験した人は
読み飛ばして続きを作れ、LANから入った人や手順を忘れた人も、その場から入門できる。

## 2. XYZ軸は、作るための足場

教材には、整地、XYZ軸を描く、XYZ軸を消す、の三つを入れる。

- 軸は正と負を見分けられるよう、負の方向を点線にする。軸ごとにブロックを変える（これまでの教材では、xがダイヤモンドか石、
  yがシーランタン、zが金）
- 軸の交点を仮想原点にする（これまでの教材ではyが95か96）。教材と作業場所に合わせた設定の例で、どのワールドでも同じ値では
  ない。Minecraftの座標と、仮想原点から考える位置との関係は、必要になったときに調べられるようにする
- 描くのと消すのには時間待ちを入れる。一瞬で完成形を見せるより、今どこを処理しているかを見て、処理の進み方と結果を
  結び付けられるほうを取る
- 軸の色や形を変えることを主な課題にしない。軸は、点、線、面にブロックを置き、位置やブロックを変えながら作品を作るための
  足場で、必要なときに描き、消し、また描ける

普段のワールドでも使うので、教材は読み込んだだけでは地形を変えない。整地、軸を描く、軸を消すは、それぞれ何をどの範囲で
変えるかが分かるようにする。「軸を消す」は、整地の前の地形やその後に作った作品を元に戻すことではない。

## 3. すぐ隣、すぐ上に置いて、座標と結びつける

最初の操作は、一つ置いて、すぐ隣に置く、すぐ上に置く、である。xを1増やすと隣へ、yを1増やすと上へ動くことを、置いた
ブロックで確かめる。Steveの立っている位置を調べて座標で読むこと、2点を決めると直方体（箱）が決まり、yが同じなら1枚の板に
なることも、この空間で見て分かる。

変数x、y、zを作り、どれか一つを変えながら置くと、線になる。変える量を2にすると点線になる。キーを押すたびに一つ置いて
変数を変えると、空中に描くように線を伸ばせる。どれも、見た結果から座標と変数の関係を考える入口にする。

## 4. 並行動作は、試して分かる

軸を描いている途中で別のスクリプトを動かすと、変数が複数の処理から書き換わって、結果が混ざることがある。教材には、これを
避ける禁止や排他制御を初めから入れない。座標に使う変数を分ければ、並行して建てられる。同じ変数を使うと、混ざる。試して
みて分かる筋にする（human owner 2026-10-20）。

「予想した形と違う」「途中から向きが変わった」と見えたことを出発点にし、動かした順序と変数を比べる。最初から正しい原因の
説明を求めない。これは、起動や保存のように安定しているべき土台の不具合を学習者へ押し付けることではない。教材の中で試せる
現象と、利用の土台は分けて考える。

Scratchの並行動作の考え方は[学習支援の設計](ai-learning-design_ja.md) §11（並列ビークル）、同じスプライトの中の干渉を仕様と
教材の題材として扱う考えは`2026-07-05-02`（保留、後継`2026-07-21-07`）にある。Scratchの変数の「すべてのスプライト用」と
「このスプライトのみ」の違いも、ここで比べられる。

## 5. マイクラ課題へつなぐ

ブロックを1個ずつ置く方式で、次の順に進む（「マイクラ課題」2021）。

```text
一個 → 柱 → 並んだ柱 → 消す（空気を置く） → 寝かせた柱 → 床 → 壁・階段 → ピラミッド
```

一個を置く操作から、繰り返し、配置、組み合わせで形を作るところへ進む。ブロックの種類を変えることも、この空間での制作の
一部にする。順番は学習の道筋で、全員が同じ速度で進むための制限にはしない。やり方がつかめたら、自分で課題を決めて挑戦する。

## 6. 短い案内から、調べられる説明へ

最初の案内は短くするが、仕組みを隠し続けない。まず動くものを使い、結果を見て、一か所を変え、その理由を調べられるように
する。年齢や「初心者／上級者」の分類より、その人が今知りたいことから説明を選べるようにする。

| 利用者の疑問 | つなぐ説明・操作 |
| --- | --- |
| このブロックを押すと何が送られるのか | WireScopeで一回の操作を見る |
| 同じことをPythonでできるか | 同じ形を作るPythonの例と比べる（これまでの教材の`axis_flat.py`は、軸を描く、消す、整地を同じ分け方で持つ） |
| 期待した結果と違ったのはなぜか | 画面、値、実行の順序を残して比べる |
| 座標の上限と下限はどこか | 自分で置いて確かめる |

Scratchを卒業してPythonへ進む一方向の階段にしない。同じワールドで、見えるブロックと文字のプログラムを行き来し、同じ操作を
別の表し方から理解する。マイクラ課題をPythonで書くことは、その一つの道である。WireScopeは最初に読む通信の仕様ではなく、
知りたくなった操作を見る入口として置く。言葉でうまく説明できなくても、画面や値、短いメモを残せるようにする。

## 7. まだ決めていないこと、確かめていないこと

- 教材の実物の名前、版、置き場所、配り方。human ownerが作り直している
- 数値：仮想原点のy、軸の長さ、整地の範囲、マイクラ課題の座標。これまでの教材はMinecraft 1.16.5（海面y=62、下限y=0）の
  ころの値で、今の版と箱庭の建築範囲に合わせて見直す
- 箱庭サーバーでの建築原点の扱いと、教材の座標との関係
- 消す処理の範囲は、教材の実物で確かめる
- PythonとScratchで同じ形を作る例の対応のさせ方
